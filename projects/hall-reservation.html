NEU Hall Reservation & Events

Coordinating campus spaces and reservation workflows.

The problem

University Hall and Multipurpose Hall reservations need coordinated scheduling, access controls and a way to prevent overlapping bookings.

My contribution

I contributed full-stack development, JWT authentication, role-based access and conflict detection. As Scrum Master, I also led sprint planning and backlog grooming.

Technical decision

The React interface connects to an Express and MongoDB backend. Conflict checks compare the same hall and date, excluding rejected reservations. Two time intervals overlap when the requested start is before the existing end and the requested end is after the existing start. Server-side validation is necessary even when the interface also checks conflicts.

Integration challenge

I worked through CORS configuration and serverless database connection-pooling failures during deployment. These issues connected frontend behavior with API and database lifecycle decisions.

Validation and current scope

Source inspection confirms client and server conflict checks. The image is a local prebuilt interface with sample state and blocked backend requests. That build may differ from the latest source. It demonstrates the interface, without establishing a live booking service or current end-to-end deployment health.
